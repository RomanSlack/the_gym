<h1 align="center">The Gym</h1>

<p align="center"><b>A luxury Nordic gym built into a forest ravine in Elverum, Norway.<br>Designed entirely through conversation between a person and an AI.</b></p>

<p align="center"><img src="docs/img/readme/hero_gorge.jpg" alt="The building bridging the gorge"></p>

<p align="center">
<b>4</b> floors stepping down a rock ravine &nbsp;·&nbsp; <b>0</b> interior columns &nbsp;·&nbsp; <b>155</b> pieces of furniture and fittings designed from scratch &nbsp;·&nbsp; <b>157</b> cameras &nbsp;·&nbsp; <b>1,490</b> render versions you can replay
</p>

Roman describes it; Claude builds it as data, drawings and 3D; then we iterate. Four floors step down the ravine to below the river surface:
- a waist-high river window and a pool with underwater windows
- a lounge bridge over the water
- a sod-roof sauna by the stream
- a drop-in daycare with a sunken garden
- a 2-mile forest loop

It's also an experiment: **can a person and an AI picture the same building and get it to real, buildable quality, purely through conversation?** Every step is recorded, so the iteration can be replayed with the prompt behind each decision.

## How it fits together

- `model/building.json` is the single source of truth for the new design. Everything else is generated from it.
- `blueprint/` is the 2D drawing set. Run `cd blueprint && npm install && npm run dev`, then open http://localhost:5280. Sheets can be linked by hash, e.g. `#A-301`. Edits to the model show up live.
- Gym V2 is drawn in grey as the "existing survey". The new design will be drawn in black on top of it.
- Coordinates match Blender world (x east, y north, z up, metres). Elevations are relative to ±0.00 = Floor 1 (Blender z −3.47).

## Not to be confused with

`~/temp/astra-experiment/nordic_gym/FOSS_Nordic_Gym.blend` is an earlier, separate, fully vibe-coded attempt (generated by `scripts/build_gym.py`). It is **not** the source of truth for this project.

## Replay

Open the drawings and press **H** (or "Replay history"). Every version of the design is shown with the prompt that led to it.
- ◀ ▶ (or ← →) step through versions, Space plays, and the timeline ticks are placed by real time.
- Any sheet and zoom works while scrubbing.
- Data comes from `tools/replay/build_history.py` (git history + archived transcripts → `blueprint/public/history/`, git-ignored). It's rebuilt automatically after every turn.

## Render replay (3D)

`python3 tools/replay/render_history.py` (also run after every turn) pulls every version of every construction render out of git history into `.capture/renders/` and writes `.capture/renders/replay.html`: pick a camera, scrub or play through its versions, with the prompt (and any messages sent mid-turn) under each frame.

## Replay capture

- Every commit carries `Prompt:`, `Prompt-Time:` and `Session-Id:` trailers, plus an `Also-Prompt:` line for every other message since the previous commit (including messages sent while Claude was mid-turn). They're added by `tools/capture/prepare-commit-msg` (enabled with `git config core.hooksPath tools/capture`, once per clone).
- A Stop hook auto-commits anything left uncommitted after each turn.
- Full transcripts are archived locally in `.capture/sessions/` (not pushed). Terrain runs are versioned in `terrain/runs/`, with animation frames in `.capture/terrain/`.
- Older commits (before 2026-10-10 20:10) can be matched to prompts by timestamp from the archived transcript.
